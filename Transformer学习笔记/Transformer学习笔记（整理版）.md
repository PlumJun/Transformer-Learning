## 符号与维度约定

全文统一采用：**一个 Token 对应一行向量，一个序列对应一个矩阵**。实际代码通常还包含批次维度。

| 符号 | 含义 | 示例或形状 |
| --- | --- | --- |
| $`B`$ | 批次大小 | 一个 Batch 中的样本数 |
| $`L`$ | 当前序列的长度 | Token 数量 |
| $`L_E`$、$`L_D`$ | 源序列、目标输入序列的长度 | 二者可以不同 |
| $`V_{\mathrm{vocab}}`$ | 词表大小 | 与注意力中的 $`V`$ 矩阵区分 |
| $`d=d_{\mathrm{model}}`$ | 模型隐藏维度 | 课程常用 $`512`$ |
| $`h`$ | 注意力头数 | 课程常用 $`8`$ |
| $`d_k`$ | 单头 Query、Key 的维度 | 常取 $`d/h`$ |
| $`d_v`$ | 单头 Value 的维度 | 常取 $`d/h`$，不必总等于 $`d_k`$ |
| $`d_{\mathrm{ff}}`$ | FFN 中间层维度 | 课程常用 $`2048`$ |
| $`X`$ | 一层注意力的输入表示 | $`L\times d`$ |
| $`Q,K,V`$ | 查询、键、值矩阵 | 由当前输入和投影参数计算得到 |
| $`A`$ | 注意力权重矩阵 | 自注意力中为 $`L\times L`$ |
| $`M`$ | 加到注意力分数上的掩码 | 允许位置为 $`0`$，屏蔽位置为 $`-\infty`$ |

> **与课程图片对照**：有些图片把单个 Token 写成列向量，使用 $`q=W^Qx`$；本文使用行向量，写成 $`q=xW^Q`$。只要同时调整权重矩阵的形状，两种约定表达的是同一类运算。不要把两套约定混在同一次维度计算中。

## 1. 模型整体架构

### 1.1 Encoder 与 Decoder 分别做什么？

经典 Transformer 用于把一个序列转换为另一个序列，例如机器翻译。

| 部分 | 接收什么 | 主要作用 | 产生什么 |
| --- | --- | --- | --- |
| Encoder，编码器 | 完整源序列 | 在源序列内部交换信息，形成上下文表示 | 每个源位置的隐藏向量 |
| Decoder，解码器 | 目标前缀与 Encoder 输出 | 结合已知目标历史和源序列信息 | 用于预测下一个 Token 的隐藏向量 |
| 输出层 | Decoder 最后一层的隐藏向量 | 映射到目标词表并计算概率 | 下一个 Token 的概率分布 |

![课程图：Transformer 整体架构与模块名称](<所用图片/Pasted image 20261017141408.png>)

*课程图 1：左侧为 Encoder，右侧为 Decoder；每个大模块内部包含多个子层。图中的输出“字符概率”更准确地应理解为词表中各个 Token 的概率。*

Encoder 的一层通常包含：

1. 多头自注意力。
2. 逐位置 FFN。
3. 围绕上述每个子层的残差连接与归一化。

Decoder 的一层通常包含：

1. 带因果约束的多头自注意力。
2. 查询 Encoder 输出的多头交叉注意力。
3. 逐位置 FFN。
4. 围绕上述每个子层的残差连接与归一化。

图中的 $`N\times`$ 表示**堆叠 $`N`$ 层结构相同的网络**。不同层通常使用不同参数，“结构相同”不等于“共享同一组权重”。

### 1.2 从文本到输出的完整路径

```text
源文本 → 分词 → Token ID → Embedding + 位置编码
      → Encoder 堆叠 → 源序列上下文表示 H_E

目标前缀 → Token ID → Embedding + 位置编码
        → Decoder 堆叠（因果自注意力 + 交叉注意力 + FFN）
        → 词表投影 → Softmax → 下一个 Token 的概率分布
```

图中的 `Output Embedding` 是 **Decoder 输入侧的目标 Token 嵌入层**，并不是最终把向量变成文字的输出层。最终预测由顶部的 `Linear + Softmax` 完成。

### 1.3 为什么生成的结果还要作为输入？

在通常的自回归生成中，模型根据已有前缀预测下一个 Token：

```math
p(y_1,\ldots,y_T\mid s)
=\prod_{t=1}^{T}p(y_t\mid y_{1:t-1},s),
```

其中 $`s`$ 为源序列，$`y_{1:t-1}`$ 为此前的目标 Token。

例如，先根据起始标记预测“我”，再根据“起始标记 + 我”预测“爱”，然后继续生成。

![课程手写图：已生成的目标内容反馈给 Decoder](<所用图片/Pasted image 20261017141519.png>)

*课程图 2：展示源句输入、目标前缀与生成结果之间的关系。*

> **理解要点**：“大模型一个字一个字吐出”可以作为直觉，但准确单位是 **Token**。一个 Token 可能是一个字、一个词、词的一部分，或其他文本片段。自回归推理逐步生成；训练时则可以并行计算多个位置的预测。

### 1.4 经典 Transformer 与其他结构

本笔记中“Encoder 理解输入、Decoder 生成输出”的分工，针对图示的 Encoder–Decoder 架构。Transformer 也可以只使用编码器式堆叠，或只使用带因果约束的解码器式堆叠。**不能把经典架构中的交叉注意力当作所有 Transformer 都有的模块。**

**本节要点**：先分清源序列、目标前缀和预测结果，再看各模块如何传递信息。

## 2. Token 与词嵌入

### 2.1 文本为什么要先数字化？

模型处理的是数值张量。文本通常先经过分词器，得到 Token，再转换为词表中的整数 ID。

```text
文本 → Token 序列 → Token ID 序列 → 向量序列
```

例如，为便于演示，假设分词结果为：

| Token | I | love | you |
| --- | --- | --- | --- |
| 假设的 Token ID | 0 | 1 | 2 |

这些 ID 只是查表索引。ID 为 2 并不表示这个 Token 在语义上是 ID 为 1 的两倍。

### 2.2 Embedding 本质上是可学习的查找表

设词嵌入矩阵为：

```math
E\in\mathbb{R}^{V_{\mathrm{vocab}}\times d}.
```

ID 为 $`u`$ 的 Token 对应第 $`u`$ 行：

```math
e_u=E[u,:]\in\mathbb{R}^{1\times d}.
```

对长度为 $`L`$ 的序列查表后，得到形状为 $`L\times d`$ 的向量矩阵；带批次时为 $`B\times L\times d`$。这种“输入索引、输出向量”的接口也体现在 [PyTorch Embedding 文档](https://docs.pytorch.org/docs/stable/generated/torch.nn.Embedding.html)中。

![课程图：词嵌入矩阵、独热向量与词向量空间](<所用图片/Pasted image 20261017135232.png>)

*课程图 3：图中采用列向量约定，嵌入矩阵画成 $`d\times V_{\mathrm{vocab}}`$；本文统一采用其转置形式。二维散点是高维词向量的直观示意。*

概念上，查表等价于独热向量乘矩阵：

```math
e_u=\mathrm{onehot}(u)E.
```

实际实现通常直接按 ID 索引，不需要真的构造庞大的独热向量。

![课程手写示意：Token ID 与对应的词向量](<所用图片/Pasted image 20261017151943.png>)

*课程图 4：ID 用于选择向量；向量中的具体数值由训练学习得到，图中数值仅为示例。*

### 2.3 需要区分的三个概念

| 概念 | 是什么 | 是否依赖当前上下文 |
| --- | --- | --- |
| Token ID | 词表索引 | 通常不依赖 |
| 词嵌入 $`e_u`$ | 该 Token 的可学习向量 | 同一嵌入表中的同一 ID 查到同一行 |
| 隐藏表示 $`x_i`$ | 经过位置编码和网络处理的向量 | 会随位置、上下文和层数变化 |

因此，同一个 Token 在不同句子中可以拥有不同的**上下文化表示**，即使最初查到的 Embedding 相同。

### 2.4 点积是不是语义相似度？

点积可以用作匹配分数，但它同时受到向量方向与长度影响：

```math
u\cdot v=\lVert u\rVert\lVert v\rVert\cos\theta.
```

若希望减少向量长度的影响，可以使用余弦相似度：

```math
\mathrm{cosine}(u,v)
=\frac{u\cdot v}{\lVert u\rVert\lVert v\rVert}.
```

> **理解要点**：不要把“原始词向量点积大”直接等同于“两个词语义一定更相近”。向量空间的性质来自训练目标；注意力中计算的更是投影后的 $`q_i`$ 与 $`k_j`$ 的匹配程度。

**本节要点**：Embedding 把离散的 ID 变成可学习的连续向量；$`512`$ 是一个维度配置，而不是 Token 向量的固定长度。

## 3. 位置编码

### 3.1 为什么需要位置信息？

单纯的词嵌入告诉模型“这里是什么 Token”，并不直接告诉模型“它位于哪里”。没有位置机制、也没有引入顺序的掩码等约束时，自注意力对输入位置的共同置换具有等变性，难以仅凭内容区分词序。

例如，“机器人抓取杯子”和“杯子抓取机器人”包含相同词语，含义却不同。

经典正弦位置编码把位置信息加到词向量上：

```math
X_i=e_i+PE(i).
```

经典论文的嵌入输入还包含 $`\sqrt d`$ 缩放，即 $`X_i=\sqrt d\,e_i+PE(i)`$；讲解位置编码时通常省略这个缩放，不影响对相加结构的理解。

![课程图：正弦位置编码公式、热力图与逐元素相加](<所用图片/Pasted image 20261017153750.png>)

*课程图 5：热力图的一行对应一个位置的编码，一列对应一个特征维度。图中的 $`d=3`$ 是截取奇数维编码的演示；下面用完整 sin/cos 配对的偶数维例子讲解。*

### 3.2 正弦位置编码公式

设 $`d`$ 为偶数，位置从 $`pos=0`$ 开始：

```math
PE(pos,2i)=\sin\left(\frac{pos}{10000^{2i/d}}\right),
```

```math
PE(pos,2i+1)=\cos\left(\frac{pos}{10000^{2i/d}}\right),
\qquad i=0,1,\ldots,\frac d2-1.
```

这里需要区分：

- $`pos`$：Token 在序列中的位置。
- $`i`$：第几组 sin/cos，也可以理解为频率组的索引。
- $`2i`$、$`2i+1`$：该组对应的两个向量维度下标。

例如 $`d=8`$：

| 组索引 $`i`$ | sin 所在维度 | cos 所在维度 | 共同分母 |
| --- | --- | --- | --- |
| 0 | 0 | 1 | $`1`$ |
| 1 | 2 | 3 | $`10`$ |
| 2 | 4 | 5 | $`100`$ |
| 3 | 6 | 7 | $`1000`$ |

所以原先关于 $`i`$ 的疑问可以明确为：**$`i`$ 不是在逐个枚举全部维度，而是在枚举频率组；每组占两个维度。**

### 3.3 一个四维的计算例子

当 $`d=4`$ 时：

```math
PE(pos)=\left[\sin(pos),\cos(pos),
\sin\left(\frac{pos}{100}\right),
\cos\left(\frac{pos}{100}\right)\right].
```

| 位置 | 第 0 维 | 第 1 维 | 第 2 维 | 第 3 维 |
| --- | ---: | ---: | ---: | ---: |
| 0 | 0.000000 | 1.000000 | 0.000000 | 1.000000 |
| 1 | 0.841471 | 0.540302 | 0.010000 | 0.999950 |
| 2 | 0.909297 | −0.416147 | 0.019999 | 0.999800 |

对整个序列，$`PE`$ 的形状是 $`L\times d`$，与词嵌入矩阵逐元素相加，结果仍为 $`L\times d`$。因此，同一 Token 出现在不同位置时，加入位置编码后的向量通常不同。

### 3.4 为什么一组中同时使用 sin 和 cos？

令 $`\omega_i=10000^{-2i/d}`$，这一组的位置编码为：

```math
\begin{bmatrix}
\sin(\omega_i pos)\\
\cos(\omega_i pos)
\end{bmatrix}.
```

根据三角函数和角公式，位置平移 $`\Delta`$ 后：

```math
\begin{bmatrix}
\sin(\omega_i(pos+\Delta))\\
\cos(\omega_i(pos+\Delta))
\end{bmatrix}
=
\begin{bmatrix}
\cos(\omega_i\Delta)&\sin(\omega_i\Delta)\\
-\sin(\omega_i\Delta)&\cos(\omega_i\Delta)
\end{bmatrix}
\begin{bmatrix}
\sin(\omega_i pos)\\
\cos(\omega_i pos)
\end{bmatrix}.
```

这个变换矩阵只依赖相对位移 $`\Delta`$。这为模型学习相对位置关系提供了可利用的结构，而不只是给每个位置贴一个无规律的编号。

另一种观察方法是：同一频率组中，两个位置编码的点积满足

```math
\sin(\omega_i m)\sin(\omega_i n)
+\cos(\omega_i m)\cos(\omega_i n)
=\cos\bigl(\omega_i(m-n)\bigr).
```

对完整的偶数维位置编码，点积是不同频率下这些项的和，仍只依赖位置差。**这不意味着实际 Attention 的分数只依赖位置差**：实际输入还包含词嵌入，并经过可学习的 Q/K 投影。

### 3.5 为什么要有多种频率？

高频维度随位置变化较快，低频维度变化较慢。组合多种频率，可以在不同尺度上表示位置变化。

> **补充理解**：正弦编码提供了便于学习位置关系的数学结构，但并不保证模型一定学会某种关系，也不保证在任意长的序列上都能可靠泛化。它是一种位置方案，不能代表所有 Transformer 的位置机制。

**本节要点**：位置编码与词向量同维，相加后维度不变；sin/cos 配对使相对位移具有规则的线性变换关系。

## 4. 自注意力：从直觉到矩阵计算

### 4.1 自注意力在解决什么问题？

仍用原笔记中的例子，假设人为分为四个 Token：

```text
机器人 / 抓取 / 红色 / 杯子
```

理解“杯子”在当前句子中的含义，需要参考“红色”和“抓取”等上下文。自注意力让每个位置根据当前表示，有选择地聚合其他允许访问位置的信息。

```math
\text{原来的 Token 表示}
\longrightarrow
\text{融合上下文的 Token 表示}.
```

输入四个 Token，通常仍输出四个位置的向量。变化的是表示内容，而不是 Token 数量。

### 4.2 Q、K、V 分别是什么？

| 名称 | 直觉 | 在计算中的作用 |
| --- | --- | --- |
| Query，$`Q`$ | 当前想获取什么信息 | 与其他位置的 Key 计算匹配分数 |
| Key，$`K`$ | 可以通过什么特征被匹配到 | 作为匹配依据 |
| Value，$`V`$ | 实际提供什么信息 | 被注意力权重加权并汇总 |

可以类比在图书馆找书：检索需求对应 Q，书的检索标签对应 K，书中的内容对应 V。

**Q 和 K 决定如何分配权重，V 提供被聚合的信息。** 这些都是模型计算出的数值向量，类比中的“需求”“标签”并不是人工输入的文字。

> **理解要点**：把 V 理解为“原信息的提纯”不够准确。V 是用于传递和聚合的可学习投影，既可能保留信息，也可能重新组合或压缩信息，没有“自动更纯”的保证。

### 4.3 第一步：生成 Q、K、V

设输入为 $`X\in\mathbb{R}^{L\times d}`$：

```math
Q=XW^Q,\qquad K=XW^K,\qquad V=XW^V,
```

其中：

```math
W^Q,W^K\in\mathbb{R}^{d\times d_k},
\qquad W^V\in\mathbb{R}^{d\times d_v}.
```

对第 $`i`$ 个 Token：

```math
q_i=x_iW^Q,\qquad k_i=x_iW^K,\qquad v_i=x_iW^V.
```

在**同一层、同一注意力头**中，所有位置共享同一组 $`W^Q,W^K,W^V`$；不同位置产生不同向量，是因为输入 $`x_i`$ 不同。不同头、不同层通常使用不同参数。

Q、K 使用不同投影，允许模型分别学习“如何发起查询”和“如何被查询”。因此，即使来源都是 $`X`$，也不要求 $`Q=K`$，注意力权重也不必对称。

### 4.4 第二步：计算匹配分数

第 $`i`$ 个位置查询第 $`j`$ 个位置的分数为：

```math
s_{ij}=\frac{q_i k_j^\top}{\sqrt{d_k}}.
```

例如，第一个位置的 Query 要分别与四个 Key 匹配：

```math
[s_{11},s_{12},s_{13},s_{14}].
```

![课程图：Query 与各个 Key 匹配并计算注意力权重](<所用图片/Pasted image 20261017203334.png>)

*课程图 6：课程先用点积说明匹配；完整的缩放点积注意力还要除以 $`\sqrt{d_k}`$。图中顶部第二项重复标成了 $`\alpha'_{1,1}`$，按位置应为 $`\alpha'_{1,2}`$。*

为什么除以 $`\sqrt{d_k}`$？在一个简化假设下，若 Q、K 各分量独立、均值为 0、方差为 1，则点积的方差会随 $`d_k`$ 增大。缩放可以缓和分数幅度增长，降低 Softmax 过早变得过于尖锐的倾向，有助于优化稳定；它不是对梯度问题的绝对保证。

### 4.5 第三步：沿 Key 维度做 Softmax

加入掩码后：

```math
A_{ij}=\frac{\exp(s_{ij}+M_{ij})}
{\sum_{r=1}^{L}\exp(s_{ir}+M_{ir})}.
```

在每一行至少有一个允许位置时：

```math
A_{ij}\geq 0,\qquad \sum_j A_{ij}=1.
```

也就是说，**固定一个 Query，把它对所有 Key 的分数一起归一化**，而不是对整个矩阵共同归一化，也不是按列归一化。

沿用原截图的数值例子，假设已经缩放后的分数为 $`[2,1,0,1]`$：

| Key 位置 | 1 | 2 | 3 | 4 |
| --- | ---: | ---: | ---: | ---: |
| 分数 | 2 | 1 | 0 | 1 |
| Softmax 权重 | 0.5344 | 0.1966 | 0.0723 | 0.1966 |

到此只得到“关注谁、关注多少”，还没有执行 V 的加权聚合。这里的行和为 1 指 **Softmax 后、注意力 Dropout 前**的权重。

### 4.6 第四步：用权重对 V 加权求和

第一个 Token 的注意力输出为：

```math
o_1=A_{11}v_1+A_{12}v_2+A_{13}v_3+A_{14}v_4.
```

第二个 Token 则为：

```math
o_2=A_{21}v_1+A_{22}v_2+A_{23}v_3+A_{24}v_4.
```

![课程图：按照注意力权重汇总 Value](<所用图片/Pasted image 20261017212733.png>)

*课程图 7：课程中的 $`b^1,b^2`$ 对应本文的 $`o_1,o_2`$，表示注意力输出向量。*

不同 Query 使用的是**同一组 K 和 V**，但通常得到不同的权重分布，从而形成不同的输出。

权重较大的位置，其 Value 被乘上的系数更大；实际向量贡献还受 Value 的大小、方向以及后续运算影响。因此，不能把单个注意力权重直接看作完整的语义解释。

### 4.7 用一个公式概括矩阵计算

```math
\boxed{
O=\mathrm{Attention}(Q,K,V;M)
=\mathrm{softmax}\left(\frac{QK^\top}{\sqrt{d_k}}+M\right)V
}
```

自注意力的维度流向为：

| 运算或张量 | 形状 | 含义 |
| --- | --- | --- |
| $`X`$ | $`L\times d`$ | 输入序列表示 |
| $`Q`$、$`K`$ | $`L\times d_k`$ | 查询和匹配特征 |
| $`V`$ | $`L\times d_v`$ | 待聚合的信息 |
| $`QK^\top`$ | $`L\times L`$ | 每个 Query 对每个 Key 的匹配分数 |
| $`A`$ | $`L\times L`$ | 每行是一套注意力分布 |
| $`O=AV`$ | $`L\times d_v`$ | 每个 Query 位置的聚合结果 |

![课程图：自注意力的完整矩阵计算](<所用图片/Pasted image 20261018095113.png>)

*课程图 8：行表示 Query 位置，列表示 Key 位置；右下角 $`AV`$ 才是信息聚合结果。图中将 Value 维度也标成了 $`d_k`$，属于 $`d_v=d_k`$ 的简化配置。*

**本节要点**：$`W`$ 是训练得到的参数，Q/K/V 是当前输入产生的中间张量，$`A`$ 是当前输入的注意力权重，$`O`$ 是聚合后的向量；四者不能混为一谈。

## 5. 多头注意力

### 5.1 为什么需要多个注意力头？

同一组 Token 之间可能存在多种关系。多头注意力让模型用不同投影参数，在不同表示子空间中分别计算注意力，再融合结果。

例如，对于“将桌子上的红色杯子放到盘子左边”，不同头**可能**侧重：

| 可能关注的关系 | 直观例子 |
| --- | --- |
| 属性 | 红色与杯子 |
| 动作对象 | 放与杯子 |
| 起始位置 | 桌子与杯子 |
| 目标位置 | 盘子左边与杯子 |

这是帮助理解的示例。实际各头的分工由训练形成，可能重叠，也不保证一个头只表示一种可命名的关系。

### 5.2 各头分别计算，再拼接

第 $`r`$ 个注意力头为：

```math
Q_r=XW_r^Q,\quad K_r=XW_r^K,\quad V_r=XW_r^V,
```

```math
\mathrm{head}_r
=\mathrm{softmax}\left(\frac{Q_rK_r^\top}{\sqrt{d_k}}+M\right)V_r.
```

多头输出为：

```math
\mathrm{MHA}(X)
=\mathrm{Concat}(\mathrm{head}_1,\ldots,\mathrm{head}_h)W^O,
```

其中：

```math
W^O\in\mathbb{R}^{(hd_v)\times d}.
```

![课程图：多头并行计算、拼接与输出投影](<所用图片/Pasted image 20261018135300.png>)

*课程图 9：各头使用同一个输入序列，但具有不同的投影参数。课程图将单头输出写作 $`Z_r`$。*

> **补充说明**：实现时可以用一次大矩阵乘法完成多组投影，再拆成多个头；不必真的用循环逐头计算。概念上各头具有不同投影参数，不代表实现上必须分开调用。

### 5.3 一个维度例子

取课程配置 $`d=512`$、$`h=8`$，常见设置为：

```math
d_k=d_v=\frac{512}{8}=64.
```

| 步骤 | 形状 |
| --- | --- |
| 输入 | $`L\times512`$ |
| 每个头的输出 | $`L\times64`$ |
| 8 个头沿特征维拼接 | $`L\times512`$ |
| 乘 $`W^O`$ 后 | $`L\times512`$ |

带批次时，单头计算通常组织为 $`B\times h\times L\times d_k`$ 等形状；拼接时合并的是头与特征维，**不是把序列长度变成 $`hL`$**。

### 5.4 为什么拼接，而不直接相加或平均？

拼接先保留各头输出的独立特征通道。直接相加或平均会提前把不同头混合在一起，难以保留“信息来自哪个头”的区分。

拼接本身只是排列数值，不含可学习的融合规则。后面的 $`W^O`$ 负责学习如何组合这些特征。

### 5.5 为什么还需要输出投影矩阵？

它主要有两个作用：

1. **可学习地融合各头特征**，为后续模块提供适合使用的表示。
2. **把拼接结果映射到所需模型维度**，从而与残差分支保持形状一致。

> **理解要点**：$`W^O`$ 不一定执行降维。在上面的常见配置中，拼接前后分别为 $`8\times64=512`$ 和 $`512`$，因此 $`W^O`$ 是 $`512\times512`$，重点在于特征混合。只有当 $`hd_v\ne d`$ 时，它才改变特征维数。

**本节要点**：多头的关键是多组投影、多套注意力分布与可学习融合；序列长度保持不变。

## 6. 填充掩码：忽略无效位置

### 6.1 为什么要 Padding？

在常见的稠密张量批处理方式中，一个 Batch 的序列会补齐到相同长度，以便组成统一形状的张量。例如，沿用原笔记的人为分词：

| 样本 | 原序列 | 补齐后 |
| --- | --- | --- |
| A | 我 / 喜欢 / 机器人 | 我 / 喜欢 / 机器人 / `<pad>` / `<pad>` |
| B | 我 / 喜欢 / 学习 / 人工智能 / 机器人 | 我 / 喜欢 / 学习 / 人工智能 / 机器人 |

`<pad>` 是占位符，真实 Token 不应把这些位置当作有效语义来源。

> 补齐是常见的批处理实现方式，并非 Transformer 数学结构要求所有输入永远等长。不同 Batch 可以有不同长度；使用其他数据组织方式时，也不一定需要统一填充。

### 6.2 Padding Mask 在哪里起作用？

它作用于 **Softmax 之前的注意力分数**：

```math
A=\mathrm{softmax}\left(\frac{QK^\top}{\sqrt{d_k}}+M_{\mathrm{pad}}\right),
```

```math
(M_{\mathrm{pad}})_{ij}=
\begin{cases}
0,&\text{第 }j\text{ 个 Key 是有效位置},\\
-\infty,&\text{第 }j\text{ 个 Key 是填充位置}.
\end{cases}
```

当 Key 位置 $`j`$ 为 Padding 时，对应 $`A_{ij}=0`$，它的 Value 不会被真实 Query 聚合。

对于 `[我, 喜欢, 机器人, <pad>, <pad>]`，一个典型的 Key 填充掩码为：

```math
M_{\mathrm{pad}}=
\begin{bmatrix}
0&0&0&-\infty&-\infty\\
0&0&0&-\infty&-\infty\\
0&0&0&-\infty&-\infty\\
0&0&0&-\infty&-\infty\\
0&0&0&-\infty&-\infty
\end{bmatrix}.
```

**行是 Query，列是 Key，所以屏蔽作为信息来源的 Padding 时，重点是屏蔽相应列。** 这与 [PyTorch MultiheadAttention 的 Key Padding Mask 定义](https://docs.pytorch.org/docs/stable/generated/torch.nn.MultiheadAttention.html)一致。

![课程图：填充掩码与注意力计算](<所用图片/Pasted image 20261018152919.png>)

*课程图 10：展示 Padding 位置如何参与张量组织，以及掩码应在 Softmax 前加入。*

> **读图提示**：图中把无效 Query 对应的一整行也设为 $`-\infty`$，并画成 Softmax 后全为 0。这不能直接作为普通 Softmax 的计算结果：一整行全被屏蔽时，常规实现可能得到 NaN。通常屏蔽无效 Key 的列，并在后续忽略无效 Query 的输出或按需置零；不要依靠“整行 $`-\infty`$”自然得到零向量。

### 6.3 Padding 输出与损失还要单独处理

只屏蔽 Key 后，Padding Query 仍可能从有效 Key 聚合出一个非零向量；这不表示 Key 掩码失效。只要后续正确忽略这些无效位置，它们就不应影响有效结果。

在训练中，还需要在损失函数里忽略 Padding 标签。两种机制解决的问题不同：

| 机制 | 解决什么问题 |
| --- | --- |
| 注意力中的 Padding Mask | 阻止有效 Token 读取填充位置的信息 |
| 损失中的 Padding 忽略规则 | 不把填充位置当作需要预测的正确答案 |

即使把 `<pad>` 的初始 Embedding 设为零，也不能替代 Mask：位置编码、偏置和后续计算都可能让填充位置出现非零表示；即便其 Value 恰好为零，它仍可能占用注意力权重。

### 6.4 不只 Encoder 需要填充掩码

- Encoder 自注意力：屏蔽源序列中的 Padding Key。
- Decoder 自注意力：屏蔽目标输入中的 Padding Key，并结合因果约束。
- Decoder 交叉注意力：屏蔽 Encoder 输出中对应的源 Padding 位置。

**本节要点**：Padding Mask 在保持批量张量形状的同时，阻止无效填充位置干扰有效信息聚合。

## 7. 因果掩码：限制信息流向

### 7.1 “因果”指什么？

这里的因果约束指：**目标序列位置 $`i`$ 只能访问自己和之前的输入位置，不能访问后面的输入位置。**

在右移输入的下一 Token 预测任务中，当前位置输入是此前的目标 Token，因此“可以看自己”并不等于“可以看到当前要预测的答案”。具体对齐方式见[训练章节](#training)。

因果掩码定义为：

```math
(M_{\mathrm{causal}})_{ij}=
\begin{cases}
0,&j\leq i,\\
-\infty,&j>i.
\end{cases}
```

四个位置的例子：

```math
M_{\mathrm{causal}}=
\begin{bmatrix}
0&-\infty&-\infty&-\infty\\
0&0&-\infty&-\infty\\
0&0&0&-\infty\\
0&0&0&0
\end{bmatrix}.
```

因此，**加性掩码的上三角是 $`-\infty`$，允许访问的位置在含对角线的下三角**。注意区分“Mask 矩阵”和“允许访问矩阵”的相反含义。

### 7.2 训练时为什么必须限制未来信息？

训练时完整目标序列已知，右移后的目标输入可以一次性送入 Decoder。没有因果约束，较早位置就可能直接读到后面输入中的正确答案，导致训练目标被泄漏。

![课程图：训练中的因果掩码与下三角注意力](<所用图片/Pasted image 20261019080908.png>)

*课程图 11：未来位置在 Softmax 前被屏蔽，对应注意力权重为 0。图中 Decoder 的 X 是右移后的输入；监督标签应与它错开一位，不能把输入与标签当成相同序列。*

因果掩码并不要求逐个位置执行训练。模型仍可以用矩阵乘法并行计算同一层所有位置，只是在计算图中禁止未来位置向过去位置传递信息。

**并行计算解决效率问题，因果掩码保证每个预测只使用允许的历史。**

### 7.3 推理时本来没有未来，Mask 还重要吗？

原笔记中的直觉对“只算最新一个 Query”的增量解码很有帮助，但需要区分计算方式。

| 推理方式 | 是否需要落实因果约束 | 如何理解 |
| --- | --- | --- |
| 一次并行处理整个目标前缀或 Prompt | 需要 | 较早位置不能读取前缀中较晚位置；通常使用三角掩码或等价内核 |
| 使用 KV Cache，每次只处理一个新 Token | 需要，但显式三角掩码可能是多余的 | 当前 Query 的 Key 集合只有有效历史与当前位置，没有未来可访问 |
| 一次处理多个新 Token，并复用已有缓存 | 需要 | 新 Token 之间仍要按绝对位置限制未来访问 |

![课程图：推理中随着前缀增长的因果注意力](<所用图片/Pasted image 20261019082652.png>)

*课程图 12：展示不断增长的目标前缀。图中画出整个前缀的注意力矩阵；增量解码可以只计算新增位置。*

为什么不能把并行前缀处理中的掩码一概省掉？即便只取最后位置的输出，在多层网络中，较早位置也可能先读取较晚位置，下一层再把这些信息传给其他位置，改变模型在训练时学习的信息依赖关系。

> **更准确的结论**：因果约束必须满足，但不一定通过一个显式存储的三角矩阵实现。单 Token 增量解码能省去显式三角掩码，前提是 Key 集合确实只包含允许的有效位置；Padding、未填满的缓存槽位等仍需要正确屏蔽。

### 7.4 因果掩码与填充掩码可以组合

使用加性表示时：

```math
M=M_{\mathrm{causal}}+M_{\mathrm{pad}}.
```

只要某个连接违反其中一个约束，就不应参与注意力。实现布尔掩码时，可以用逻辑运算组合，但必须先确认 API 规定的 True/False 含义。

### 7.5 写代码时的两个常见坑

1. **不同 API 的布尔含义可能相反**：`nn.MultiheadAttention` 的布尔 Mask 中 `True` 表示屏蔽；`functional.scaled_dot_product_attention` 的布尔 `attn_mask` 中 `True` 表示允许参与。不能不加转换就直接复用。[官方 SDPA 文档](https://docs.pytorch.org/docs/stable/generated/torch.nn.functional.scaled_dot_product_attention.html)
2. **带缓存时要按实际位置对齐**：当 Query 只有一个新位置、Key 却包含很长的历史时，不能把一个从左上角开始的普通三角矩阵直接当作正确的因果关系。应使用适合该接口的掩码或位置处理方式。

**本节要点**：训练可以并行，信息依赖仍然是从过去到未来；推理时是否需要显式 Mask，要看实际计算了哪些 Query 和 Key。

## 8. 交叉注意力：查询另一个序列

### 8.1 为什么 Decoder 还需要查询 Encoder？

假设翻译任务为：

```text
源序列：我 / 喜欢 / 打 / 篮球
目标序列：I / like / playing / basketball
```

Decoder 的因果自注意力让它获取目标前缀的信息；交叉注意力让它根据当前生成需求，从 Encoder 的源序列表示中读取相关信息。

例如，已知目标前缀是 `I like`，预测后续内容时，模型还需要参考源句中的“打篮球”。

| 注意力类型 | Q 来自哪里 | K、V 来自哪里 | 信息交互范围 |
| --- | --- | --- | --- |
| 自注意力 | 当前序列 | 同一序列 | 一个序列内部 |
| 交叉注意力 | 查询序列 | 另一个序列 | 两个序列之间 |

### 8.2 Q、K、V 的准确来源

在经典 Decoder 的一层中：

- $`H_D`$：当前层因果自注意力子层及其相应残差、归一化处理后的目标隐藏表示。
- $`H_E`$：Encoder 最后一层的源序列输出。

于是单头交叉注意力为：

```math
Q=H_DW^Q,\qquad K=H_EW^K,\qquad V=H_EW^V,
```

```math
O=\mathrm{softmax}\left(\frac{QK^\top}{\sqrt{d_k}}+M_{\mathrm{src-pad}}\right)V.
```

**Q 提出当前需求，K 提供匹配依据，V 提供源序列信息。** K、V 并非把 Encoder 原先自注意力中的中间 K/V 原封不动拿过来；它们由当前交叉注意力层自己的投影矩阵计算。

![课程图：交叉注意力的矩阵表示](<所用图片/Pasted image 20261019084749.png>)

*课程图 13：Q 的行数取决于目标输入长度，K/V 的行数取决于源序列长度。原图用 `ball` 对应“篮球”，正文改用更准确的 `basketball`。*

> **读图提示**：右下注意力矩阵最后一行给出的数值为 $`0.1+0.15+0.15+0.3=0.7`$，不满足 Softmax 后每行和为 1 的条件，应视为绘图数值笔误。矩阵形状与计算流程仍可用来理解交叉注意力。

### 8.3 源与目标长度为什么可以不同？

设：

```math
H_D\in\mathbb{R}^{L_D\times d},\qquad
H_E\in\mathbb{R}^{L_E\times d}.
```

则：

| 张量 | 形状 |
| --- | --- |
| $`Q`$ | $`L_D\times d_k`$ |
| $`K`$ | $`L_E\times d_k`$ |
| $`V`$ | $`L_E\times d_v`$ |
| $`A`$ | $`L_D\times L_E`$ |
| $`O=AV`$ | $`L_D\times d_v`$ |

例如，$`L_D=5`$、$`L_E=4`$、$`d_v=3`$：

```math
\underbrace{A}_{5\times4}
\underbrace{V}_{4\times3}
=\underbrace{O}_{5\times3}.
```

输出位置数跟随 **Query 的位置数**。K 和 V 则必须对齐到同一组被查询位置，不能任意使用不同的序列长度。

### 8.4 输出究竟是什么？

**交叉注意力输出的是上下文向量，而不是翻译词，也不是词表概率。**

例如 $`o_{\text{like}}=[0.4,0.8,-0.2]`$ 是一个示意向量，表示 `like` 所在目标位置从源序列读取的特征。这三个数并不直接表示 `playing` 的概率。

采用右移输入时，各行可以这样理解：

| Decoder 输入位置 | 交叉注意力输出的用途 |
| --- | --- |
| `<bos>` | 为预测 `I` 提供源序列信息 |
| `I` | 为预测 `like` 提供源序列信息 |
| `like` | 为预测 `playing` 提供源序列信息 |
| `playing` | 为预测 `basketball` 提供源序列信息 |
| `basketball` | 为预测 `<eos>` 提供源序列信息 |

这些信息还要经过多头拼接与 $`W^O`$、残差连接、归一化、FFN，以及后续 Decoder 层。只有在最后一层之后，才由词表投影和 Softmax 产生最终的下一 Token 分布。

```text
目标上下文 → 生成 Q
源序列表示 → 生成 K、V
           → 跨序列匹配与聚合
           → 更新目标位置表示
           → 后续网络处理 → 词表投影 → 预测下一个 Token
```

### 8.5 常见疑问

**为什么不用一个固定的源句汇总向量？**

因为不同目标位置可能需要不同源信息。交叉注意力允许不同的 Q 形成不同权重，从而按需读取源序列，而不是每一步都只能接收相同的固定汇总。

**为什么 `like` 的交叉注意力中没有 `I`？**

因为这里的 K/V 来自源序列；目标前缀中的 `I` 已经可以在此前的因果自注意力中被访问。两种注意力承担不同的信息读取任务，并按顺序协作。

**交叉注意力需要目标侧三角掩码吗？**

在完整源句已知的经典翻译任务中，通常不需要按目标时序对源位置施加三角掩码；但要屏蔽源 Padding。目标未来信息由此前的因果自注意力限制。若是流式输入等特殊任务，则要按任务另外限制可访问的源位置。

**交叉注意力只适用于翻译吗？**

它的本质是让一组表示查询另一组表示。因此，同样的计算形式也可以连接不同模态或不同来源的特征；具体哪一侧产生 Q，需要看模型设计。

**本节要点**：交叉注意力让目标位置按自身需求读取源信息，输出长度随 Q，输出内容仍是隐藏特征。

## 9. 残差连接

### 9.1 计算形式

残差连接的基本形式很简单：

```math
Y=X+F(X).
```

$`F`$ 可以是注意力子层或 FFN 子层。对于自注意力，$`F(X)_i`$ 可能依赖多个位置，不能把它误认为只使用 $`x_i`$ 的独立运算。

相加要求两条分支的形状兼容。Transformer 通常把子层输出映射回模型维度 $`d`$，以便与输入相加。

### 9.2 从前向传播理解

以“杯子”的表示为例：

- 原表示 $`x_{\text{杯子}}`$ 通过直接路径传递。
- 注意力子层读取上下文，产生对该位置的更新 $`F(X)_{\text{杯子}}`$。
- 两者相加，得到新的位置表示。

```math
y_{\text{杯子}}
=x_{\text{杯子}}+F(X)_{\text{杯子}}.
```

这样，子层可以在已有表示上学习补充和修正；当某个子层不需要明显改变表示时，它可以学习接近零的更新。

这里的“保留原信息路径”不代表相加后可以无损拆回全部原信息，也不代表每个层都必须只做很小的修改。

### 9.3 从反向传播理解

对简化的单个残差块：

```math
\frac{\partial y}{\partial x}
=I+\frac{\partial F(x)}{\partial x}.
```

恒等项 $`I`$ 提供直接的梯度路径，有助于缓解深层网络的优化困难。

> **补充说明**：这不是“有残差就绝不会梯度消失或爆炸”的保证。实际梯度还取决于网络深度、归一化位置、初始化等。上述导数针对 $`y=x+F(x)`$；若外面还有 LayerNorm，则完整导数还要乘上 LayerNorm 的雅可比矩阵。

### 9.4 与 Add & Norm 的关系

课程图中的 Add & Norm 是“残差相加 + LayerNorm”。经典 Post-LN 写法为：

```math
Y=\mathrm{LN}\bigl(X+\mathrm{Dropout}(F(X))\bigr).
```

Dropout 在训练时随机丢弃部分分支输出，在通常的评估模式下关闭。残差和 LayerNorm 的先后关系，见下一节。

**本节要点**：残差给已有表示加上可学习更新，同时为信息和梯度提供直接通路。

## 10. 层归一化 LayerNorm

### 10.1 归一化的是谁？

在这里讨论的标准 Transformer 用法中，对每个 Token 的 $`d`$ 个特征计算均值和方差。

若张量形状是 $`B\times L\times d`$，并使用 `LayerNorm(d)`，归一化沿最后的特征维进行：

```text
固定一个样本 b，固定一个位置 i：
[x₁, x₂, …, x_d] → 计算该向量自己的均值与方差 → 归一化
```

**不会把不同 Token 或不同样本混在一起计算统计量。**

![课程图：LayerNorm、BatchNorm 与归一化示意](<所用图片/Pasted image 20261018160149.png>)

*课程图 14：用于直观理解归一化。对 Transformer，应落实到“每个 Token 自己的特征维”。右侧优化等高线仅作示意，不能据此认为 LayerNorm 一定把损失曲面变成圆形。*

### 10.2 完整公式

对单个 Token 的向量 $`x=[x_1,\ldots,x_d]`$：

```math
\mu=\frac1d\sum_{j=1}^{d}x_j,
\qquad
\sigma^2=\frac1d\sum_{j=1}^{d}(x_j-\mu)^2.
```

```math
\mathrm{LN}(x)_j
=\gamma_j\frac{x_j-\mu}{\sqrt{\sigma^2+\epsilon}}+\beta_j.
```

| 符号 | 含义 |
| --- | --- |
| $`\mu`$ | 当前 Token 特征的均值 |
| $`\sigma^2`$ | 当前 Token 特征的方差 |
| $`\sqrt{\sigma^2+\epsilon}`$ | 加稳定项后的标准差形式 |
| $`\epsilon`$ | 数值稳定用的小正数 |
| $`\gamma,\beta\in\mathbb{R}^{d}`$ | 可学习的逐特征缩放与偏置 |

同一 LayerNorm 模块的 $`\gamma,\beta`$ 通常在各样本、各位置间共享，不同归一化模块通常各有一组参数。这些细节可对照 [PyTorch LayerNorm 文档](https://docs.pytorch.org/docs/stable/generated/torch.nn.LayerNorm.html)。

> **读图提示**：图中若用 $`\sigma`$ 作分母，应理解为标准差，不能同时把它称为方差；实际公式还应包含 $`\epsilon`$。另外，“均值约 0、方差约 1”描述的是仿射变换前的标准化结果，不是任意 $`\gamma,\beta`$ 作用后的最终输出。

### 10.3 一个数值例子

沿用原截图：

```math
x=[2,4,6,8],\qquad y=[100,200,300,400].
```

对 $`x`$：

```math
\mu_x=5,\quad \sigma_x^2=5,
\quad \frac{x-\mu_x}{\sqrt{\sigma_x^2}}
\approx[-1.3416,-0.4472,0.4472,1.3416].
```

$`y=50x`$，在忽略 $`\epsilon`$、且尚未施加可学习仿射变换时，会得到相同的标准化结果。

这说明 LayerNorm 可以减少整体平移和尺度差异；它不会把各维度都变成相同数值。与此同时，归一化也会去掉部分整体均值、尺度信息，不能笼统说“归一化完全不损失信息”。

### 10.4 为什么有助于训练？

随着层数增加，注意力、线性变换和激活可能让中间特征的数值尺度变化。LayerNorm 对每个位置独立规范特征尺度，并允许模型通过 $`\gamma,\beta`$ 学习合适的调整，有助于稳定优化。

它不依赖同一 Batch 中其他样本的统计量，适合序列长度和批次组织发生变化的情况。它与 BatchNorm 的差异首先在于统计维度与使用方式，不能简单理解成“LayerNorm 是专门处理变长序列的模块”。

### 10.5 Post-LN 与 Pre-LN

省略 Dropout 时，常见的两种顺序是：

| 形式 | 单个子层的写法 | 顺序 |
| --- | --- | --- |
| Post-LN | $`Y=\mathrm{LN}(X+F(X))`$ | 子层计算 → 残差相加 → 归一化 |
| Pre-LN | $`Y=X+F(\mathrm{LN}(X))`$ | 归一化 → 子层计算 → 残差相加 |

课程中的经典结构图采用 Post-LN。Pre-LN 把归一化放到子层之前，通常还在整个堆叠之后使用最终归一化。两者会影响梯度传播和优化行为，不能混用公式后仍视为完全相同的结构。[关于 Pre-LN 与 Post-LN 的原始研究](https://arxiv.org/abs/2002.04745)

本笔记后面的经典架构计算以 Post-LN 为准；阅读其他模型代码时，应先确认归一化位置。

**本节要点**：LayerNorm 处理一个 Token 内部的特征尺度，不承担跨 Token 信息交换。

## 11. 前馈神经网络 FFN

### 11.1 FFN 的核心作用

注意力子层让不同位置交换信息；标准逐位置 FFN 对每个位置已有的特征做非线性加工。

```math
\text{读取上下文后的特征}
\longrightarrow
\text{重新组合、非线性加工}
\longrightarrow
\text{新的特征表示}.
```

这里的 Feed-Forward 指信息沿前向计算图从输入到输出传递，没有循环状态；**不表示训练时没有反向传播**。

### 11.2 标准计算形式与维度

采用行向量约定，经典 FFN 为：

```math
\mathrm{FFN}(x)
=\mathrm{ReLU}(xW_1+b_1)W_2+b_2,
```

其中：

```math
W_1\in\mathbb{R}^{d\times d_{\mathrm{ff}}},
\qquad W_2\in\mathbb{R}^{d_{\mathrm{ff}}\times d}.
```

课程常用的维度变化为：

```math
512\xrightarrow{W_1,b_1}2048
\xrightarrow{\mathrm{ReLU}}2048
\xrightarrow{W_2,b_2}512.
```

| 步骤 | 做什么 | 形状变化 |
| --- | --- | --- |
| 第一次线性变换 | 组合输入特征，产生更多中间通道 | $`L\times d\to L\times d_{\mathrm{ff}}`$ |
| 非线性激活 | 学习非线性的特征关系 | 形状不变 |
| 第二次线性变换 | 组合中间特征，映射回模型维度 | $`L\times d_{\mathrm{ff}}\to L\times d`$ |

![课程图：前馈网络中的线性映射与维度变化](<所用图片/Pasted image 20261018200858.png>)

*课程图 15：展示线性映射如何改变特征维度。完整的经典 FFN 还包含两次线性映射之间的非线性激活，不能只看成矩阵乘两次。*

### 11.3 “逐位置”与“共享参数”是什么意思？

对序列中的每个位置，执行相同形式的计算：

```math
y_i=\mathrm{FFN}(x_i).
```

同一层的所有 Token 使用同一组 $`W_1,b_1,W_2,b_2`$，不同层通常使用不同参数。虽然各位置独立计算，但可以同时用一个张量运算完成。

**标准 FFN 不直接从其他 Token 读取信息**。不过它的输入已经经过注意力处理，所以加工的特征可以包含上下文。

### 11.4 保留原例子：组合“红色”和“杯子”特征

为了理解非线性组合，假设一个 Token 的表示中有两个抽象特征：

```math
x=[r,c],
```

其中 $`r`$ 表示“红色”的程度，$`c`$ 表示“杯子”的程度。把它们暂时简化为 0 或 1，一个隐藏神经元可以计算：

```math
a=\mathrm{ReLU}(r+c-1.5).
```

| 红色特征 $`r`$ | 杯子特征 $`c`$ | $`r+c-1.5`$ | 激活输出 $`a`$ |
| --- | --- | ---: | ---: |
| 0 | 0 | −1.5 | 0 |
| 1 | 0 | −0.5 | 0 |
| 0 | 1 | −0.5 | 0 |
| 1 | 1 | 0.5 | 0.5 |

只有两种特征同时存在时，该隐藏神经元才输出正值。这说明“分别拥有两个特征”和“形成一个联合特征”是不同的。

真实 FFN 有大量隐藏通道，能够学习多种组合，再把结果映射回模型维度。

> **例子的边界**：真实隐藏向量的维度不一定能直接命名为“红色”“杯子”，语义通常分布在多个方向和多个维度上。这里是人为构造的计算示例，不是对训练后神经元含义的断言。

### 11.5 为什么非线性不可少？

如果删掉激活函数：

```math
(xW_1+b_1)W_2+b_2
=x(W_1W_2)+(b_1W_2+b_2).
```

两次仿射变换仍然可以合并为一次仿射变换，单纯升维再降维不会自动带来这类非线性表达能力。

经典课程结构使用 ReLU；其他模型可以采用不同激活或 FFN 结构。学习时应区分“标准两层 FFN 的例子”和“所有 Transformer 的固定写法”。

**本节要点**：Attention 在位置之间交换信息，FFN 在每个位置内部加工特征；升维提供中间通道，非线性提供更丰富的组合能力。

## 12. 训练：右移输入、并行预测与参数更新

### 12.1 先把整个网络串起来

本节以经典 Post-LN Encoder–Decoder 翻译模型为例，省略 Dropout 的记号。

Encoder 的一层：

```math
U=\mathrm{LN}_1\bigl(X+\mathrm{MHA}_{\mathrm{self}}(X;M_{\mathrm{src-pad}})\bigr),
```

```math
H=\mathrm{LN}_2\bigl(U+\mathrm{FFN}(U)\bigr).
```

Decoder 的一层：

```math
D_1=\mathrm{LN}_1\bigl(D+\mathrm{MHA}_{\mathrm{causal}}(D;M_{\mathrm{tgt}})\bigr),
```

```math
D_2=\mathrm{LN}_2\bigl(D_1+\mathrm{MHA}_{\mathrm{cross}}(D_1,H_E;M_{\mathrm{src-pad}})\bigr),
```

```math
D_{\mathrm{out}}=\mathrm{LN}_3\bigl(D_2+\mathrm{FFN}(D_2)\bigr).
```

其中：

- $`M_{\mathrm{tgt}}`$ 同时实施目标侧因果约束与填充约束。
- 交叉注意力中，第一个输入产生 Q，第二个输入 $`H_E`$ 产生 K/V。
- 每处 LayerNorm、每个子层和每一层通常都有各自的参数；公式中的局部下标不表示 Encoder 和 Decoder 共享参数。
- 这些子层更新隐藏特征，词表输出层放在整个 Decoder 堆叠之后。

### 12.2 训练输入与标签如何错开？

沿用原笔记的例子：

```text
源句：我 / 是 / 一条 / 狗
目标：I / am / a / dog / <eos>
```

训练时使用真实目标历史，这称为 **Teacher Forcing**。通过右移构造 Decoder 输入：

| 位置 | 1 | 2 | 3 | 4 | 5 |
| --- | --- | --- | --- | --- | --- |
| Decoder 输入 | `<bos>` | I | am | a | dog |
| 监督标签 | I | am | a | dog | `<eos>` |

第 $`t`$ 个预测位置能使用的目标信息是：

```math
\langle\mathrm{bos}\rangle,y_1,\ldots,y_{t-1},
```

对应标签为 $`y_t`$。例如，输入 `am` 所在位置预测 `a`；**不是输入 `am`、再把复制出 `am` 当作这个位置的任务**。

`<bos>` 表示序列开始，`<eos>` 表示序列结束；具体模型可能采用不同的特殊 Token 约定，这里沿用课程写法。

### 12.3 Encoder 编码源序列

源句经过分词、词嵌入和位置编码，再经过 Encoder，得到：

```math
H_E=\mathrm{Encoder}(s).
```

这里把输入准备过程合并在 Encoder 记号中。$`H_E`$ 是一组源位置向量，而不必压缩成唯一的句子向量。

经典离线翻译的完整源句已知，Encoder 可以访问整个有效源序列。Decoder 的“不能看未来”限制主要针对目标侧，不意味着源句中的较后位置也必须隐藏。

### 12.4 Decoder 并行计算所有位置的预测

把右移后的目标序列一次送入 Decoder，并施加因果掩码：

```math
H_D=\mathrm{Decoder}(y_{\mathrm{in}},H_E).
```

各个位置在**同一网络层内**可以并行计算；不同网络层之间仍存在前后依赖。

![课程图：各目标位置的监督损失与反向传播](<所用图片/Pasted image 20261018215516.png>)

*课程图 16：各输出位置分别与正确标签计算损失，梯度可以经交叉注意力回传至 Encoder。图下方被划线的真实目标 Token 在 Teacher Forcing 训练中仍作为右移输入使用；这里不应理解成训练只输入 `<bos>`。*

### 12.5 从隐藏向量得到词表分布

设 Decoder 最后一层用于预测 $`y_t`$ 的行向量为 $`h_t\in\mathbb{R}^{1\times d}`$：

```math
\ell_t=h_tW_{\mathrm{vocab}}+b_{\mathrm{vocab}},
\qquad
W_{\mathrm{vocab}}\in\mathbb{R}^{d\times V_{\mathrm{vocab}}}.
```

这里 $`\ell_t`$ 是词表上所有候选 Token 的 **logits，未归一化分数**：

```math
p_t=\mathrm{softmax}(\ell_t),
\qquad
p(y_t\mid y_{1:t-1},s)=(p_t)_{y_t}.
```

要区分：

| 名称 | 内容 | 长度 |
| --- | --- | --- |
| 隐藏向量 $`h_t`$ | 网络内部特征 | $`d`$ |
| logits $`\ell_t`$ | 每个词表候选的分数 | $`V_{\mathrm{vocab}}`$ |
| 概率 $`p_t`$ | Softmax 后的候选分布 | $`V_{\mathrm{vocab}}`$ |
| Token ID | 选定或监督的词表索引 | 一个整数 |

输出投影 $`W_{\mathrm{vocab}}`$ 与多头注意力的输出投影 $`W^O`$ 是不同模块，不要混淆。

### 12.6 交叉熵损失如何计算？

对普通的单正确标签交叉熵：

```math
\mathcal{L}_t=-\log p(y_t\mid y_{1:t-1},s).
```

例如，正确 Token 的概率为 0.8 时，损失约为 0.223；概率为 0.1 时，损失约为 2.303。损失越小，表示模型给正确 Token 分配的概率越高，但不等同于整个生成任务已经完成得好。

设一个 Batch 中的有效目标位置集合为 $`\mathcal{I}`$，则：

```math
\mathcal{L}
=\frac{1}{|\mathcal{I}|}\sum_{(b,t)\in\mathcal{I}}\mathcal{L}_{b,t}.
```

有效位置通常包括需要学习预测的 `<eos>`，不包括补齐的 `<pad>`。单条没有 Padding 的序列则可写成：

```math
\mathcal{L}=\frac1T\sum_{t=1}^{T}\mathcal{L}_t.
```

> **实现补充**：PyTorch 的 `CrossEntropyLoss` 接收 logits，并在内部完成相应的对数概率计算；通常不要先手动 Softmax 再传给它。可以使用 `ignore_index` 忽略填充标签。上面的公式说明普通交叉熵；启用标签平滑等设置时，目标与损失表达需要相应调整。[CrossEntropyLoss 官方文档](https://docs.pytorch.org/docs/stable/generated/torch.nn.CrossEntropyLoss.html)

### 12.7 反向传播与参数更新

用 $`\theta`$ 表示所有可训练参数，根据损失计算梯度：

```math
\nabla_\theta\mathcal{L}.
```

最简单的梯度下降更新是：

```math
\theta_{\mathrm{new}}
=\theta_{\mathrm{old}}-\eta\nabla_\theta\mathcal{L},
```

其中 $`\eta`$ 为学习率。Adam 等优化器会采用不同的更新规则；上式用于理解“根据梯度调整参数”的基本过程，不是 Adam 的完整公式。

在没有冻结参数的端到端训练中，梯度可以经 Decoder 的交叉注意力传到 Encoder，联合更新词嵌入、Encoder、Decoder 和输出层。

> **配置说明**：经典 Transformer 原论文使用 Adam，不能把“常用 AdamW”当作原论文的具体配置。架构本身也不绑定唯一的优化器。[原论文训练设置](https://arxiv.org/html/1706.03762v7#S5.SS3)

### 12.8 原有疑问：并行训练会不会各个 Token 各更新一次参数？

通常不会。在一次普通训练步中：

1. 使用当前同一套参数，计算多个有效位置的预测。
2. 汇总这些位置的损失。
3. 对汇总损失反向传播。
4. 优化器执行一次参数更新。

因为求导具有线性性质：

```math
\nabla_\theta\mathcal{L}
=\frac1T\sum_{t=1}^{T}\nabla_\theta\mathcal{L}_t.
```

多个位置共同贡献梯度，不是在同一组参数上同时执行互相独立、互相冲突的多次更新。若使用梯度累积，则可以汇总多个微批次的梯度后再更新，但这是额外的训练组织方式。

### 12.9 为什么训练能并行，而生成通常不能？

Teacher Forcing 已经提供真实的历史 Token，因此后一个训练位置不必等待前一个位置的**模型预测结果**。

推理时没有真实目标历史可直接提供，下一步输入依赖上一轮实际生成的 Token，所以通常要逐步生成。

“训练时知道正确答案”的准确含义是：**训练过程持有标签和真实历史，但每个预测位置仍通过掩码被限制为只能读取合法前缀。**

```text
训练数据
   ↓
源序列编码 + 右移目标输入
   ↓
带掩码的并行前向计算
   ↓
各位置 logits 与标签计算损失
   ↓
汇总有效位置损失 → 反向传播 → 优化器更新
```

**本节要点**：右移输入确定预测对齐，因果掩码防止泄漏，Teacher Forcing 支持位置并行，汇总损失共同驱动参数更新。

## 13. 推理：自回归生成与 KV Cache

### 13.1 一次完整的生成过程

继续使用翻译例子：

```text
源序列：我 / 是 / 一条 / 狗
```

1. Encoder 编码完整源句，得到 $`H_E`$。
2. Decoder 从 `<bos>` 或已有目标前缀开始。
3. 因果自注意力读取已知目标历史。
4. 交叉注意力读取源序列表示。
5. 最后一层隐藏向量经词表投影得到 logits，形成下一 Token 分布。
6. 按解码策略选择一个 Token，把它加入目标前缀。
7. 重复上述生成步骤，直到遇到 `<eos>` 或达到长度等停止条件。

![课程图：自回归推理中生成结果逐步反馈给 Decoder](<所用图片/Pasted image 20261018214232.png>)

*课程图 17：黄色 O 是输出投影和概率计算模块的示意，不是某个“英文单词神经元”；箭头表示生成结果成为后续输入。*

理想生成示例：

| 当前目标输入前缀 | 本步选择的 Token |
| --- | --- |
| `<bos>` | I |
| `<bos> I` | am |
| `<bos> I am` | a |
| `<bos> I am a` | dog |
| `<bos> I am a dog` | `<eos>` |

标准推理中，模型参数保持固定；**变化的是输入前缀、隐藏状态和缓存，而不是每生成一个 Token 就训练一次模型**。

### 13.2 “选择下一个 Token”不总是取最大概率

常见策略包括：

| 策略 | 基本做法 |
| --- | --- |
| 贪心解码 | 每步选择当前概率最高的 Token |
| 采样 | 从经过温度、候选筛选等处理的分布中抽取 Token |
| Beam Search | 保留多条候选前缀并比较序列得分 |

课程图中的单条生成路径可用贪心解码帮助理解；具体策略会影响输出。训练中计算交叉熵通常不需要先对预测结果做离散采样。

选出的 ID 最后交给分词器的解码过程，组合成用户看到的文字。

### 13.3 KV Cache 缓存了什么？

如果每生成一步都重新计算整个目标前缀，会重复计算很多历史位置的信息。

在满足因果约束、参数固定的常规推理中，已有位置的表示不依赖以后才生成的 Token，因此可以复用每层此前算出的 Key 和 Value。

对某一层、某一个头，第 $`t`$ 个已知输入位置可写为：

```math
K_{\leq t}=\mathrm{Concat}(K_{1:t-1},k_t),
\qquad
V_{\leq t}=\mathrm{Concat}(V_{1:t-1},v_t),
```

```math
o_t=\mathrm{softmax}\left(\frac{q_tK_{\leq t}^{\top}}{\sqrt{d_k}}\right)V_{\leq t}.
```

这里省略了仍可能需要的 Padding 或无效缓存槽位掩码。处理位置 $`t`$ 得到的隐藏表示用于预测下一个 Token。

需要记住：

- 缓存通常是**每一层各自的 K/V**，不是只缓存最初的 Embedding。
- 逐步生成时通常只需要新增位置的 Q，不必复用所有历史 Q 来重新计算历史输出。
- 缓存必须与当前前缀、位置编号和有效长度正确对应。
- 缓存减少重复计算，但会占用随有效上下文长度增长的存储空间。

这些机制可对照 [Hugging Face 关于 KV Cache 的说明](https://huggingface.co/docs/transformers/main/cache_explanation)。

### 13.4 Prefill 与 Decode

| 阶段 | 处理什么 | 注意力特点 |
| --- | --- | --- |
| Prefill，前缀预处理 | 一次处理已有的目标前缀或 Prompt | 多个位置并行，落实因果约束，并建立缓存 |
| Decode，增量解码 | 每次处理新加入的目标 Token | 新 Query 读取历史缓存与当前 K/V |

在典型的 Decoder-only 文本生成中，Prompt 先经过 Prefill，再逐 Token Decode。在经典翻译模型中，完整源句由 Encoder 编码，目标侧则按相同的自回归原则处理前缀。

对于一次只处理一个新 Query 的全注意力解码，在模型维度固定时，该 Query 与历史 K 的匹配、以及对 V 的聚合，计算量随可访问历史长度线性增长。**这不表示生成整个长序列的总开销变成线性，也不表示模型不再计算 Attention。**

### 13.5 Encoder 输出是否也要反复算？

同一条源句生成目标序列时，Encoder 输出通常只需计算一次。各 Decoder 层交叉注意力中的源 K/V 也可在该层计算后复用，因为源表示不随目标生成改变。

注意：不同 Decoder 层通常具有不同的交叉注意力投影，所以不能把某一层算出的 K/V 当作所有层共享的缓存。

### 13.6 训练与推理对照

| 维度 | Teacher Forcing 训练 | 通常的自回归推理 |
| --- | --- | --- |
| 目标历史来自哪里 | 真实目标序列 | 已有前缀与模型生成结果 |
| 一次计算哪些位置 | 通常并行计算所有训练位置 | Prefill 可并行；Decode 通常每次新增一个位置 |
| 是否有因果约束 | 有 | 有，显式 Mask 的形式可不同 |
| 主要输出 | 用于计算损失的 logits | 用于选择下一 Token 的 logits 或概率 |
| 是否更新参数 | 根据梯度更新 | 标准推理不更新 |
| 是否需要损失与反向传播 | 需要 | 通常不需要 |
| 缓存用途 | 常规全序列训练通常不复用推理式 KV Cache | 复用历史 K/V，减少重复计算 |

真实历史与生成历史之间的差异也解释了一个现象：训练时每一步都能看到正确历史，推理时早先的预测错误却可能影响后续生成。因此，单看训练损失不能完全代表实际生成效果。

**本节要点**：推理是参数固定时的条件预测循环；KV Cache 加速历史信息复用，因果约束始终要满足。

## 14. 公式与易错点速查

### 14.1 最值得记住的公式

| 模块 | 公式 | 抓住什么 |
| --- | --- | --- |
| 嵌入查表 | $`e_u=E[u,:]`$ | ID 选择对应向量 |
| 加入位置 | $`X_i=e_i+PE(i)`$ | 词信息与位置信息结合；经典配置还含嵌入缩放 |
| Q/K/V 投影 | $`Q=XW^Q,\ K=XW^K,\ V=XW^V`$ | 参数与中间向量不同 |
| 缩放点积注意力 | $`O=\mathrm{softmax}(QK^\top/\sqrt{d_k}+M)V`$ | 匹配、归一化、聚合 |
| 多头融合 | $`\mathrm{Concat}(\mathrm{head}_1,\ldots,\mathrm{head}_h)W^O`$ | 拼接后再可学习地混合 |
| 交叉注意力投影 | $`Q=H_DW^Q,\ K=H_EW^K,\ V=H_EW^V`$ | 查询方与信息提供方不同 |
| 残差 | $`Y=X+F(X)`$ | 给已有表示加更新 |
| LayerNorm | $`\mathrm{LN}(x)_j=\gamma_j(x_j-\mu)/\sqrt{\sigma^2+\epsilon}+\beta_j`$ | 每个 Token 内部归一化 |
| FFN | $`\mathrm{ReLU}(xW_1+b_1)W_2+b_2`$ | 逐位置非线性加工 |
| 输出 logits | $`\ell_t=h_tW_{\mathrm{vocab}}+b_{\mathrm{vocab}}`$ | 隐藏维映射到词表维 |
| 单位置交叉熵 | $`\mathcal{L}_t=-\log p(y_t\mid y_{1:t-1},s)`$ | 提高正确 Token 的预测概率 |

### 14.2 三种注意力放在一起看

| 类型 | Q 的来源 | K/V 的来源 | 典型掩码 | 单头输出形状 |
| --- | --- | --- | --- | --- |
| Encoder 自注意力 | 源隐藏表示 | 同一源隐藏表示 | 源 Padding | $`L_E\times d_v`$ |
| Decoder 因果自注意力 | 目标隐藏表示 | 同一目标隐藏表示 | 因果 + 目标 Padding | $`L_D\times d_v`$ |
| Decoder 交叉注意力 | 目标隐藏表示 | Encoder 最终输出 | 源 Padding | $`L_D\times d_v`$ |

### 14.3 关键纠正与边界

| 容易混淆的说法 | 更准确的理解 |
| --- | --- |
| 模型一个字一个字输出 | 自回归模型通常逐 Token 生成，Token 不等于一个汉字 |
| Transformer 的维度就是 512 | 512 是课程与经典基础配置的示例 |
| 位置公式中的 $`i`$ 是全部维度下标 | $`i`$ 是频率组索引，$`2i`$、$`2i+1`$ 才是对应维度下标 |
| 词向量点积直接表示语义相似度 | 点积也受长度影响；注意力比较的是投影后的 Q/K |
| V 是对原信息的提纯 | V 是用于聚合的可学习投影，没有自动提纯保证 |
| 每个 Token 有独立的投影矩阵 | 同一层同一头的各位置共享投影参数 |
| 注意力矩阵就是最终输出 | $`A`$ 是权重，$`AV`$ 才是单头聚合输出 |
| $`W^O`$ 总在降维 | 常见配置中拼接维度已经等于 $`d`$，它仍负责学习特征混合 |
| Padding Mask 只用于 Encoder | Decoder 自注意力和交叉注意力也可能需要相应的填充掩码 |
| 把一整行设为负无穷，Softmax 后自然全为 0 | 普通实现可能出现 NaN；应处理有效 Key 与无效 Query 的不同角色 |
| LayerNorm 在一整句之间做归一化 | 本文标准用法对每个 Token 的特征维独立处理 |
| 残差保证绝不梯度消失 | 它提供直接路径、改善优化条件，不构成绝对保证 |
| FFN 的价值只是升维再降维 | 关键还包括非线性加工和特征组合 |
| 交叉注意力直接输出英文词 | 输出的是目标位置读取到的源上下文向量 |
| 训练并行，所以各位置都能看完整目标 | 计算并行与访问权限不同；因果掩码限制每个位置的信息 |
| 训练每预测一个 Token 就更新一次参数 | 常规训练步汇总多个位置损失，再反向传播和更新 |
| 推理一定不需要 Mask | 需分清并行前缀处理与单 Token 增量解码，并处理 Padding 等约束 |
